**Right-sizing, 2026-09-05 (outside-voice verdict, accepted):** CP8 as originally scoped bundled two things of very different urgency -- the recording loop (contract, store, endpoint, on-screen capture) and the precision-at-quota metric, which will read "suppressed, n below minimum" on any realistic demo day regardless of what gets built, because too few real inspections will exist by then. Split: **CP8 is the recording loop, done below.** Precision-at-quota moves to **CP8b**, explicitly deferred. Reclaimed time goes to CP7, which is the actual finish line and needs you, not more code.

> **Kid version:** right now the system guesses which works are odd, and nobody ever tells it whether it guessed right. This checkpoint is the part where the officer's answer comes back. No model changes here at all. You cannot learn from answers you never wrote down, so this checkpoint is only about writing them down.

**Why this is a phase and not a nice-to-have.** Both the submitted deck and `Understanding NidhiNetra` already promise this: *"reviewers train the model, not the reverse"*, *"reviewer verdicts loop back in to recalibrate the models over time"*, and the strongest line in the PRD, *"Inspection outcomes come back as labels. The system generates the training data it currently lacks."* None of that is built. Today an inspection outcome has nowhere to go: `normalized_record.schema.json` has no field for it, no endpoint accepts one, and nothing stores it.

**The architectural shift this forces, stated up front.** Every artifact in the app today is *rebuildable* -- `build_snapshot()` throws away and re-derives works, scored, graph and manifest from source data on every run. An inspection outcome is the first piece of state that is **not** rebuildable: it is a human judgement that exists nowhere else and cannot be regenerated. It therefore must live somewhere `build_snapshot()` cannot overwrite, and that is a deliberate design decision, not an implementation detail to discover later.

- [x] **The outcome enum is settled.** 2026-09-05 eng review: [[NEXT-STEPS]] item 4's proposed 6-value enum adopted as canonical over an earlier, rougher inline list that lived in this file — `work_present_and_matches`, `work_present_but_differs`, `work_not_found_at_site`, `documentation_incomplete`, `duplicate_of_another_work`, `agency_unresponsive`, plus a mandatory free-text `notes` field. None of the six is a verdict ("fraud"/"clean"/"verified"/"corrupt" explicitly excluded) — every value is an observable fact an inspector can attest to on site or on paper.
- [x] **A frozen contract for an inspection outcome.** `contracts/inspection_outcome.schema.json`, built, hardened in two outside-voice passes the same session. `work_id`, `inspected_on`, `inspection_rank_at_time` + `risk_score_at_time` (frozen at write, so precision-at-quota never silently changes its own answer after a rebuild); `cutoff_rank_at_time` + `population_n_at_time` (inspection_rank spans all 79,068 works, the quota cutoff spans only the 44,810 under implementation -- two populations, only comparable if frozen together); `in_control_sample` (see CP8b); `_issue_mapping` freezing which of the six enum values count as "an issue found," same moment as the enum. **Round 2:** required `inspector_id` (the deck promises "reviewers train the model," plural -- the schema couldn't say which reviewer); denormalized `state`/`constituency`/`implementing_agency`/`work_category`/`sanctioned_amount_inr` (work_id "stability across pulls" was asserted, never observed -- an orphaned outcome stays human-readable if the portal ever re-issues IDs).

## CP9 — Learning from outcomes ☐ scoped 2026-09-03, not started
**Owner:** A2 · **Blocked by:** CP8b, and by outcome volume

> **Kid version:** once enough officers have written down what they actually found, the system can start adjusting which signals it trusts. Not before.

- [x] **Redesigned 2026-09-05, outside-voice finding:** no retraining gate at all. The original plan reused `MIN_PEER_GROUP_N=30` (a floor for a *descriptive* statistic, a median/z-score) to gate *model selection* -- requiring reweighted detector weights to beat the frozen baseline on held-out outcomes. 30 minus a holdout is roughly 8-10 test points; any reweighting "wins" on that by noise alone, which is exactly the kind of number this project refuses everywhere else. **Corrected design:** report the observed rate with a Wilson confidence interval; detector weights stay frozen, full stop. This reverses the same session's own earlier D7 decision (`MIN_OUTCOMES_FOR_REWEIGHT=30`) once a sharper statistical read caught what "same number, already defensible to a judge" actually missed -- memorable isn't the same as justified.
- [ ] **Supervised classification stays gated until confirmed cases genuinely accumulate**, which is the deck's own wording (*"save supervised classifiers for once confirmed cases pile up"*). Until then this box stays empty, and that is a correct state for it to be in, not a gap.
- [ ] **Optional bootstrap, honestly labelled:** CAG/RTI-documented cases that can be matched by hand to real MPLADS `work_id`s form a small validation set to sanity-check ranking before real inspection outcomes exist. Treated as a spot-check with its `n` stated, never as a training corpus. See [[Logbook]] 2026-09-02 10:05 and 2026-09-03 for why the distinction matters.
